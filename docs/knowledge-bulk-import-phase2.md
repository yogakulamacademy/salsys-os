# Knowledge import phase 2 — upload receipt and durable ledger candidate
Source-only, not activated. Separate from #919 preflight and P0 #917. Current main's Knowledge action uses a user-session client, active organization binding, can_manage_organization and create_source_backed_knowledge_document_v2 with p_approve:false. That RPC also allows service_role, so a worker must not treat service_role possession as tenant authorization.

## Upload design
Use private Supabase Storage and direct resumable TUS uploads (https://supabase.com/docs/guides/storage/uploads/resumable-uploads). No public bucket, no overwrite, no service-role credential in browser. Server generates UUID job and canonical org/job/source.json, with bounded reservation, upload expiry, per-tenant quotas and current admin/session check. RLS must match exact reserved job, actor, current session, active membership, expiry and path, not only folder prefix. Review existing permissive Storage policies before provisioning. Verify object size and digest server-side from actual bytes, do not trust metadata or client digest; bind immutable version/object identity and prevent replacement. Recheck permission before enqueue and each worker claim/commit. Receipt helper only previews server-owned inputs; it does not authenticate them. No token, object, job or write is issued in this PR.

## Durable design
SQL review draft under docs/sql (not migration). Metadata-only jobs and entry ledger with tenant composite key, entry index idempotency, lease metadata and bounded attempts. RLS on, application roles revoked. Still needs: validated transactional enqueue from preflight (including rejected/duplicate entries), tenant-specific quota enforcement, authorized claim using row locks and skip locked, lease renewal/reclaim, compare-and-set token/status, cancellation/expiry, retries with backoff, and transactional draft creation plus ledger finalization. Existing source-backed creation RPC and finalization must execute in SAME transaction to avoid duplicate drafts after crash; verify document tenant binding and actual current actor authority within that transaction; never log raw content or tokens. Derive progress from ledger. Add restrictive read/cancel RPCs only after independent review; no direct client table writes. Retention and object cleanup must be approved; no personal data retention period assumed. Raw source is not copied into entry ledger. Do not implement worker against unverified SQL schema.

## Acceptance
Disposable no-egress tests: tenant A/B mismatches, stale sessions, revoked admins, expired reservations, overwrite/path traversal, forged size/digest, double enqueue/claim, lease expiry and stale token, crash between create/finalize, cancellation, quotas, retention and no auto-approval. Review actual Supabase plan/bucket size and installed policies before any activation. No hosted SQL, bucket provisioning, cron/queue registration, live upload, merge/deploy or staging lift. Existing import untouched. P0 Option A and R2 holds unchanged.
