# Browser transport and history integration review
Adds an in-memory browser upload client, bounded chunk-size header compatible with browser-controlled Content-Length, and session-bound read-only history HTTP handler. Browser generates a random writer token before acquire (same token can replay lost acquire); replays all previous chunks for exact-byte verification before sending remainder, no automatic publish retry, no persistent client storage. Caller must supply actual same-origin authenticated route; no mounted route or live polling. Handler validates exact byte stream, does not trust browser content-length or tenant headers. History accepts only bounded microsecond cursor and no org argument, returns projected metadata; no raw rows or storage tokens. Readiness tests cover interruption, lost publish response, history authorization boundary and cursor precision. Actual local provider fixture now drives browser client through Request/Response handler with real verified local Auth token, staged SQL and Storage; HTTP bridge is in-process, not actual ingress, and fixture privileged database transport is not a production adapter. Fresh tests pending. Previous gateway cleanup SQL, readiness, CodeQL and capacity passed; direct-TUS provider probe remains a known rejection. No production auth bridge, route, scheduler, provider credential, polling, retention approval, reconciliation service or hosted changes. DBA/privacy approval for raw DB staging remains required.
