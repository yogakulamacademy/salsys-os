# Storage authorization and metadata history checkpoint (review only)
New owner-only SQL review functions: upload_allowed matches current Auth identity/session, tenant binding, active admin membership, exact reserved bucket/path/size, awaiting-upload state and expiry. It is only a predicate: no installed Storage RLS, signed grant, resumable endpoint, overwrite protection or actual upload. Actual Storage authorization must use a provider-enforced exact insert-only reservation (including TUS completion/replay and maximum bytes), deny update/upsert/delete and inspect all existing permissive policies. A separate verified read adapter must pin immutable object identity and recompute digest before enqueue and worker reads. Revoke new uploads on enqueue/cancel/expiry; existing tokens and incomplete resumable uploads need provider-specific revocation/cleanup proof. No bucket creation authorized.

History returns bounded keyset-paginated metadata and status counts from a current authorized organization admin session, including earlier jobs from the same organization. No raw source, path, actor, session, hash, lease token or payload. No UI/live RPC access; current grants remain revoked. Preserve microsecond timestamp cursor precision at the API boundary. Job counts include invalid/duplicate/failed/cancelled separately; pending/leased are unfinished. Cancellation remains original-session-bound in review SQL, so UI must not promise all admins can cancel. Recovery of terminal failed entries requires a new reviewed policy and operation.

Worker authorization decision: do NOT impersonate the initiating user by setting Auth JWT claims in a service worker. Separate narrowly scoped execution identity and revocable job delegation bound to org/job/actor/session, verified immutable object+manifest, expiry and exact claim token/attempt. Enforce current membership/session and revocation inside transaction. Worker must not have general service_role or direct CRM table access; use a narrowly owned database function for draft-only creation, explicit original actor attribution and atomic ledger finalization. Existing create RPC uses auth.uid(), so dedicated worker integration requires a separate reviewed internal draft-creation boundary. Worker principal, delegation persistence, verification and execution remain unimplemented; no live storage access, cleanup or job activation. Test real role grants, revoked sessions, cross-tenant jobs, expiry, worker replay and raw data exposure before wiring. Staging/production hold unchanged.
