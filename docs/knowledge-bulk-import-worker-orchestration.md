# Application worker orchestration checkpoint (review only)
Adds restricted worker source-identity and registered manifest verification functions to the review SQL. Both recheck current delegation; no tokens, raw document content or cross-job reads. The worker identity result is not proof of actual storage immutability. A bounded application runner (max 10 claims per tick; default 5) uses injected adapters for immutable source preparation, DB manifest verification, claim, finalize, receipt lookup and retry settlement. It distinguishes confirmed rollback with narrowly allowed SQLSTATE codes from unknown outcomes; unknown response without exact receipt stops without retry or settlement. Unprocessed leases expire normally. No actual scheduler, storage client, database connector or execution grant wired. Future adapters must be server-owned, validate actual source bytes against the pinned object, use PostgreSQL canonical digest, enforce transport deadlines and keep credentials out of browser. Existing upload-preparation auth checks cannot substitute for worker delegation: separately extract shared parsing/byte verification without reusing expired upload windows or fabricating actor context. Current code expects that adapter, not implemented. SQL identity/manifest checks do not independently prove storage bytes, and test fixture uses synthetic metadata. Full-size performance, UI, cleanup and complete runtime authorization remain open. Source and SQL tests added; no hosted SQL, storage, migration, merge, deployment or staging activation.
