## Gap and concrete progress

KB-09R's user-pasted HTML preview is explicitly **operator-supplied unverified text**, not crawler-fetched evidence. The existing consent-/robots-/SSRF-checked crawler (`runDiscoveryPageCore`) fetches HTML but passes only page status/title/links to the checked database commit, then loses the response bytes. Independently, the existing HTML5 parse5/structured-excerpt and source-grounded quote candidate modules work on synthetic fixtures. Simply writing an evidence row in a second RPC after page success would leave a race where consent or ownership expires, or a failed evidence INSERT leaves a page marked successful without its evidence.

KB-09S supplies a **draft-only engineering rehearsal** for the future correct boundary: reuse existing parsers on the *actual already-fetched in-memory HTML response*, and put the page outcome and small unreviewed evidence envelope into **ONE** checked SQL function/transaction in an automatically dropped local database. There is **no operational hosted collector or retention approval**, so the production adapter **does not call or install** the new RPC.

### Files and contracts

- `lib/knowledge-discovery/crawler-evidence-envelope.ts` reuses the real `prepareHtml5WebsiteEvidence` (KB-02C) and `prepareSourceGroundedDrafts` (KB-03A). The input is a prior caller-authorized HTTP-200 HTTPS page returned by the existing pinned-network crawler; the function **does not authorize fetching** on its own. It accepts at most 512 KiB of HTML, requires an exact same-host/canonical source URL, valid UTC timestamp, actual source-backed candidate output and returns at most **16 original exact source quotes** (each ≤1,400 characters) with existing quote/block/snapshot SHA-256 digests. It does not paraphrase, call a model, approve, retain or publish data. Script/nav/hidden-text rejection follows the same existing parser. Rejected/empty/unbounded text fails closed.
- `lib/knowledge-discovery/run-core.ts` now accepts an **optional fourth argument** `evidencePreparer` and an optional `evidence` argument to the single `store.commit` method. Only explicit **synthetic** adapters inject it; the existing production `runner.ts` is **unchanged** and still sends the original exact 11-field `commit_knowledge_discovery_page_with_proof_v1` payload. With the opt-in preparer enabled, extraction failure changes the outcome to `failed` rather than recording a misleading successful page without the requested evidence. When the checked DB commit refuses a mutation, core returns failed; it does not send a second write.
- `docs/sql/KB-09S-atomic-website-evidence-REHEARSAL-DRAFT.sql` is **not a migration**, and refuses execution unless the database is the random auto-dropped `salsys_kb09f_<18 hex>` test fixture, with KB-01B/06B/09M/N parent markers, synthetic sessions and no real `leads`/`contacts`. It creates a **private, RLS-enabled, synthetic-only** `kb09s_fixture.page_evidence` table with foreign keys to organization/job/page, one evidence snapshot per page, no direct API/service DML grants, forced `review_state='unreviewed'`, `publish_eligible=false`, and at most 16 validated quote hashes. Its rehearsal-only service-role RPC checks exact tenant-page-job/source URL and the envelope shape, then calls the unmodified `commit_knowledge_discovery_page_with_proof_v1`, which checks current lease/proof/consent under existing locks, and **in the same transaction** inserts evidence. Any INSERT error rolls back both the earlier page/job commit and the evidence write. A denied proof/consent/lease results in no evidence. Direct service-role table writes and anon/authenticated execution are revoked. No real source data or recurring cleanup job is generated.
- `tests/knowledge-discovery/crawler-evidence-envelope.test.mjs` exercises the **real** KB-02C and KB-03A parser pipeline with invented HTML, unsafe/offsite/noncanonical URLs, script/hidden text, hashes, deterministic output and an opt-in **one-commit** synthetic worker adapter. It checks evidence rejection never records fetched, denied mutation never appears processed, and production runner remains wired to its original metadata-only checked RPC.
- The **existing** `tests/database/knowledge-commit-ownership-races.test.mjs` disposable PostgreSQL suite applies KB-09S **last**, then verifies exact service-only RPC grants, no direct table write, an off-tenant or forged source rejected, quote hashes required, proof expiry denies, a deliberately injected evidence INSERT exception rolls back the *entire* page/worker job transaction, successful one-time storage stays **unreviewed/unpublishable**, and a replayed stale lease cannot add another snapshot.

### Explicit limits and high-risk unresolved decisions

This is **not** a real enabled durable evidence feature. The SQL table stores only **invented synthetic evidence in an auto-dropped local DB**; it has no real retention window and must not be moved to hosted Supabase. A digest of text is not independent browser-visible evidence nor proof that the website actually served those bytes. The SQL wrapper can enforce the authorized tenant/lease/proof/consent at **SQL invocation time**, but cannot guarantee valid ownership at a maliciously delayed external physical `COMMIT`. External CSS/JS-driven visibility, provenance reconciliation, non-canonical URLs with tracking queries, content versioning, consent-withdrawal/retention/erasure propagation, immutable auditor receipt design, backups/logs/providers, provider model questions, SQL owner/EXECUTE review and stable idempotent retry all require separate security/privacy/DBA decisions and **real isolated staging**.

In a future approved implementation, capture must use a **single versioned and reviewed DB migration**, an exact protected bridge RPC, approved purpose and policy-version/retention controls, complete independent race tests and explicit owner spending authorization. **Do not substitute two service-role table writes or expose draft excerpts to ordinary tenant clients**.
