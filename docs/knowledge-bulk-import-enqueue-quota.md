# Reservation and enqueue checkpoint (review only)
Owner-only review functions; no application grants or migration. Fixes malformed dollar quoting in prior retry/expiry draft. Reservation serializes on a per-organization quota row, checks current actor/session/membership, validates size, recognizes exact job-id retries, and enforces explicit active-job and retained-byte ceilings. No configured quota means denial; no production plan limits chosen. All retained jobs count toward bytes until an independently reviewed deletion/reconciliation process is built. Quota test values 1 active job/300 bytes are synthetic only. Require READ COMMITTED transaction isolation or separately verify serialization under other isolation levels before runtime adoption. Enqueue locks parent, verifies supplied byte count, source digest format and complete indexed manifest, saves ledger and job state in one transaction; exact same manifest retry returns durable status, conflicts reject. Manifest hash covers PostgreSQL jsonb canonical text in supplied array order. This does not verify storage bytes or deduplicate different job IDs or semantically identical differently ordered manifests. Real immutable storage version, trusted preflight/manifest conversion, per-entry digest, upload grant, quota accounting across retention and deletion, worker delegation and RLS remain open. CI tests exercise actual SQL with synthetic auth and data, not production credentials. No hosted execution authorized.
